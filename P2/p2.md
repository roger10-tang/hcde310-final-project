# P2: Proposal

## 1. Design problem, audience, and value

Our app is for UW students who want to play golf near Seattle and need someone to play with. They might find a tee time on a course website and still have to text friends to see who's free. In our app, they can share that tee time and see if other UW students want to play.

## 2. Depth item

We chose Multiplayer so UW students can see which tee times other students are interested in. When someone taps “I'm interested,” Flask saves it, and the page checks the server every few seconds so others can see the updated count.

## 6. Tech plan

| Route | Input | API or data | What the user sees |
|---|---|---|---|
| GET / | Date | Saved posts, GolfCore, Open-Meteo | Tee times with the course, rain chance, and interest count |
| POST /posts | Student, course, date, time | Save to tee-times.json | The new tee time in the list |
| POST /posts/&lt;id&gt;/interest | Post ID, student ID | Save to interests.json | The updated count |
| GET /counts | Date | Saved posts and interests | Counts update every few seconds |

| File | What it does |
|---|---|
| app.py | Handles routes and reads and writes JSON files |
| api.py | Gets course details and hourly rain chances |
| templates/index.html | Shows tee times and the posting form |
| static/counts.js | Refreshes the counts on the page |

## 7. Who we'll test with

We plan to ask three UW student golfers to try the app in person at the UW Golf Club range meetup. Our target date is Friday, December 4.

## 8. Success criteria
Code:

- Students can post a tee time, and it remains visible after refreshing the page.
- When a student taps "I'm interested," the interest count updates for everyone viewing the same post within 5 seconds.
- If the weather API fails, tee times still appear with "Weather unavailable."

People:
- At least 2 out of 3 UW student golfers can find a tee time and express interest without help.
- At least 2 out of 3 students understand what the interest count means.
- All 3 testers can identify the course, tee time, and rain chance on a post.

## 9. Priorities and risks

Must-have: Students can browse and post tee times, see course details and rain chances, and tap “I'm interested.” The app saves posts and interests so everyone sees the latest count.

Nice-to-have: We'd add a course filter first, then let students sort by rain chance.

Risks: If the weather request fails, tee times might disappear. We'll test that by turning off the forecast call. To check if interest counts get out of sync, we'll open one post in two browsers, tap “I'm interested” in one, and see if both counts go up by one.

## 10. AI plan
- We will use AI to help understand API documentation, check API requests, debug code, and review our project for missing error and loading states. 
- We will check AI suggestions by testing the app with real API responses and asking UW student golfers to try the main features. 
- We will make the final design decisions because the app should reflect the needs of our actual audience.
